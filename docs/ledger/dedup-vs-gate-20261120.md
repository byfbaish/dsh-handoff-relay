# 台账：同一正文复跑，测到的是去重不是闸

- 日期：2026-11-20
- 记录人：大肥鱼 · DSH 插件组（群分身，admin）
- 来源：主身 2026-11-20 16:5x 要求「别只留在回执里，写进台账」，并点明标题措辞

## 一句话

负向验收（「这件应该被拒」）**不能复用上一次用过的正文**。relay 的去重键是**内容摘要**（`index.js` 里 `digest = contentHashOfFile(...)` 前 12 位，`:582`），同一正文第二次出现会被「去重跳过 · 原因=重复(内容)」直接吞掉，**闸根本没走到**——测出来的通过是去重台账给的，不是闸给的。

## 现场（0.6.4 真机 A 轮）

第一次丢的是 0.6.2 时用过的同一句原文「0.6.2 验证件·本件无任何 @，按守卫应被拒绝，请忽略。」：

```
2026-11-20T08:23:02.430Z INFO 去重跳过 target=d3d68e801cb3 file=062-verify-no-mention.md digest=47e9534baca1 原因=重复(内容)
2026-11-20T08:23:12.425Z INFO 去重跳过 ... 同上
```

目录里既没有 `.rejected.md`、也没有被投递——看起来「安静」，很容易被误读成「拒绝了」，实际是**没进入判断**。

换成同形状但新正文（`0.6.4 验证件甲·本件没有任何 @，按守卫应被拒；请忽略。`，件 `062a-verify-at-comma.md`）才拿到真结果：

```
2026-11-20T08:24:04.803Z WARN dsh-handoff-relay watch-reject target=062a-verify-at-comma.md dir=...\bridge\to-group reason=NO_MENTION
```

## 正确的复跑做法

1. 每次负向复跑**换新正文**（哪怕只改一个字），文件名换不换都行——去重认内容不认名字。
2. 换人复跑同样要换：这条坑跟执行者无关，跟「台账里已有该 digest」有关。
3. 判「闸生效」必须三件同时看到：`watch-reject` 日志行、`.rejected.md` 落盘、`rejected.json` 有对应 finger；只有「目录安静」不算证据。
4. 若确实要复用旧正文，先清 `rejected.json`／`delivered` 里的对应 digest——但那等于改台账，别在验收里做。

## 顺带一条文案欠账（已在 0.6.5 修）

拒绝件末句原写「改好后请用新文件名重投（同名会被去重拦）」，把原因写反了：**换名字不换正文照样被拦**。0.6.5 统一改成「同内容会被去重拦（与文件名无关），改内容后重投即可」。
